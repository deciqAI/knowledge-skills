# Method in Action: The AI-Agent Pre-Flight Checklist (2023–2026)

> *Example for the [checklist](../SKILL.md) skill.*

The checklist was born in 1935 because the B-17 became "too much airplane for one man to fly." Between 2023 and 2026, software crossed the same threshold: autonomous AI agents that write code, send emails, move money, and talk to customers became too much system for one deploy to eyeball. The industry's response recapitulated aviation's — quietly, and in exactly the shape this skill teaches. The pre-deployment routine that emerged across the ecosystem (model system cards, eval suites, staged rollouts, guardrail reviews) is a checklist discipline, and the frameworks that codified it — NIST's AI Risk Management Framework (released January 2023) and the model/system-card practice frontier labs established from 2019 onward — are its WHO-surgical-checklist moment: institutional, published, adopted under pressure. Run the Process on the operation most founders now face: **shipping an autonomous agent to production.**

**Step 1 — Identify the operation.** Operation: promoting an AI agent (or a new model version powering it) to production. Frequency: high — model versions ship monthly, prompts change weekly. Stakes: an agent that emails the wrong customer, hallucinates a refund policy, or loops on a paid API does damage at machine speed. Near-miss history: the 2023–2026 trade press is a catalog of them — support bots inventing policies airlines were later held to, agents leaking prompt-injected data, cost blowups from retry loops. The failure modes are known, repeated, and — the checklist precondition — *skippable by skilled people under deadline*.

**Step 2 — List candidates.** The industry's hard-won candidate pool: evals run on the *new* model version (not inherited scores)? Regression suite against last version's known failures? Prompt-injection/jailbreak probes? Tool permissions scoped to least privilege? Spend caps and loop limits set? Rollback path tested? Human-approval gate on irreversible actions (payments, sends, deletes)? PII handling verified? Incident owner named? Monitoring dashboards live before launch?

**Step 3 — Cut to 6–10.** Killing items is the discipline. Keep what is critical, *routinely skipped by experts* ("the evals passed last month" — but the model version changed), and yes/no-verifiable. A 25-item governance doc gets skimmed; an 8-item gate gets run.

**Step 4 — Choose format.** DO-CONFIRM for a senior team shipping weekly (build freely, pause at the gate, confirm all eight before promote). READ-DO for the first agent a team ever ships, or for cross-team launches where marketing, legal, and eng each own items — the B-17 case, not the Van Halen case.

**Step 5 — Embed.** Trigger: any change to model version, system prompt, or tool scope. Owner: the engineer promoting, not a compliance function — aviation's lesson is that the operator runs the checklist, not an inspector. Consequence of skipping: the 2024–2026 enforcement and litigation record (from the SEC's AI-washing actions to customer-facing bot rulings) supplied what culture alone couldn't — an external answer to "what happens if we don't."

**Step 6 — Iterate.** Every agent incident is a candidate item. The teams that treat postmortems as checklist-diffs — one new yes/no item per real near-miss, one stale item removed per quarter — are running Pronovost's ICU loop on software. The checklist is a living artifact, which is also why generic downloaded "AI governance checklists" underperform: items earned from *your* near-misses get run; imported boilerplate gets skimmed.

**Why this case matters for the skill.** It shows the checklist's core claim holding in a brand-new domain: the failure isn't ignorance (everyone *knows* to run evals) but the reliable skipping of known steps under speed pressure — precisely the gap between knowing and doing that checklists exist to close. And it composes upstream: before the pre-flight checklist ever runs, [seven-questions-test](../seven-questions-test/SKILL.md) is the *business-level* checklist for whether the thing being shipped should exist at all.

**Founder takeaway (startup):** Your agent's demo impresses; your deploy gate is what investors' technical diligence and your first enterprise customer's security review will actually probe. Write the 8-item DO-CONFIRM gate now — evals-on-this-version, injection probe, least-privilege tools, spend cap, rollback, human gate on irreversible actions, PII check, incident owner — and make the promoting engineer own it. It costs 10 minutes a ship and is the cheapest "enterprise-ready" signal you can build.

**Founder takeaway (SMB):** Same discipline, smaller surface: before turning on any AI tool that talks to customers or touches money, a 6-item READ-DO — what can it send/spend without asking me? · did I test the 5 questions customers actually ask? · is there a human handoff? · a daily cost cap? · do I know how to turn it off? · who checks its output the first week? A restaurant's reservation bot and a Fortune-500 agent fail the same way: a known step, skipped.
